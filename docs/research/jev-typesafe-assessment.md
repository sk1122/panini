# Jev by TypeSafe AI: candidate decision model for Panini

**Checked:** 2026-09-19  
**Scope:** TypeSafe AI's official site, documentation, cookbooks, and customer agreement; Pydantic AI's first-party integration documentation. No Panini API calls, Jev calls, or performance tests were run.  
**Status:** Research and integration hypothesis, not a selection or measured Panini result.

## Bottom line

Yes, **Jev** is the name of TypeSafe AI's first “System One” model. It accepts a text or JSON *state* plus explicitly defined, typed questions, then returns bounded decisions and probabilities. It does **not** generate prose, summarize documents, write context packs, or answer open-ended questions. It is a plausible replacement for an LLM only where Panini currently asks a *small, closed-ended semantic question* after deterministic filtering and authorization. It cannot replace Panini's canonical ledger, permission checks, acceptance decisions, temporal logic, citation hashes, or an LLM used to synthesize a natural-language answer. [Introduction](https://docs.typesafe.ai/introduction), [state](https://docs.typesafe.ai/concepts/state), [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

## What the API actually does

- One request passes `state` (string, JSON object, or array of text values) and one or more independently evaluated questions. `Choice` selects from supplied options and returns their probability distribution and confidence; `Score` rates supplied ordered levels; `Noul` returns a 0–1 probability for a yes/no claim. Choice/Score confidence is computed from the distribution; Noul does **not** have a separate confidence field. [Introduction](https://docs.typesafe.ai/introduction), [primitives](https://docs.typesafe.ai/primitives), [confidence](https://docs.typesafe.ai/confidence)
- The API is `POST https://api.typesafe.ai/v1/systemone`, using a TypeSafe API key; TypeSafe documents a JavaScript/TypeScript SDK, `@typesafe-ai/sdk`, and a Python SDK. Pydantic AI also documents `typesafe:jev-latest` as a decision-model integration. [Quick start](https://docs.typesafe.ai/introduction/quickstart), [JavaScript SDK](https://docs.typesafe.ai/sdk/javascript), [Pydantic AI integration](https://pydantic.dev/docs/ai/models/typesafe/)
- The currently documented stable release is `jev-1.13.0`; `jev-latest` and `jev-preview` point to it as checked. Its documented limit is 64k tokens for the whole request and 32k for state plus the longest question. It is text-only, with English as the strongest language. TypeSafe lists $0.042 per million input tokens and free output tokens; rate limits and aliases can change. Pin the version for a controlled trial. [Models](https://docs.typesafe.ai/models)
- “Type-safe” means the answer must fit the output shape supplied by the caller, **not** that its semantic judgment is necessarily true. TypeSafe itself says Jev can get things wrong and documents adversarial steering, literal reading, weak arithmetic/date handling, indirection, and deterioration with irrelevant state. The company's “zero hallucinations” plot is a schema-match guarantee rather than an empirical claim that every judgment is factual. [Technical-results nuance](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)

## Likely Panini fit (inferences to test)

These are **integration hypotheses**, not claims of measured Panini accuracy:

| Seam | Bounded Jev question | Required non-model control |
| --- | --- | --- |
| Retrieval reranking | Does this *authorized, shortlisted* accepted entry answer the user's question? | Scope filtering and candidate generation first; do not let Jev choose inaccessible material. TypeSafe's own reranking example only reorders a shortlist; it cannot rescue an omitted candidate. [Reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe) |
| Answerability/abstention | Does any retrieved evidence actually support an answer? | Include an explicit `none`/unknown path; do not treat the highest-ranked choice as proof of answerability. TypeSafe's search cookbook pairs Choice ranking with a separate Noul existence check for exactly this reason. [Line-by-line search](https://docs.typesafe.ai/cookbooks/semantic_find) |
| Candidate triage | Is a source observation likely to be a decision, action, blocker, or ordinary chatter? | Keep it as a review/routing proposal, never accepted company memory or task state by itself. [Primitives](https://docs.typesafe.ai/primitives) |
| Evidence quality | Is this passage relevant, contradictory, or trying to instruct the downstream model? Does the cited span support this claim? | Source identity, quote/span/hash existence, authorization, and reviewer decisions remain deterministic or human-governed. TypeSafe demonstrates passage classification and citation-support checks, not evidence authority. [RAG passages](https://docs.typesafe.ai/cookbooks/classifying_rag_passages), [citation checks](https://docs.typesafe.ai/cookbooks/citation_check) |

The narrowest first pilot is **reranking and answerability on already-authorized accepted entries**. This targets the observed natural-language search miss without placing Jev in the acceptance or permissions path. Use fixed, source-grounded cases, compare the existing retrieval baseline against the same candidate pool with Jev added, and measure first-turn recall, unsupported-ready rate, latency, and cost separately. Preserve the exact model ID, question schema, candidate IDs/hashes, scores, and threshold version with each run. These pilot details are recommendations, not vendor facts.

## Unsuitable uses and operational cautions

- Do not use Jev for free-form context-pack writing, summaries, grounded answer synthesis, new entity names/IDs, or open-world extraction. TypeSafe explicitly says it does not generate text and recommends a generative model when generation is needed. [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- Do not use it to compute dates, counts, arithmetic, temporal ordering, or revocation status; keep those in code. Do not send the full company corpus as state: TypeSafe warns that irrelevant state degrades accuracy. [Jev limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- Do not treat a model's probability as a calibrated Panini-specific threshold without testing on Panini data and testing failure modes. TypeSafe advises domain-specific threshold tests; Choice confidence is distribution-derived, while Noul gives only a probability. [Confidence](https://docs.typesafe.ai/confidence)
- TypeSafe describes early access; no self-hosted Jev weights or model license were found in its official API/model documentation. Its agreement grants access to its **hosted** web interface and API. API calls would therefore send scoped Panini material to a third party. TypeSafe states it does not train on customer requests/responses and offers enterprise zero-data-retention, but ZDR is an enterprise arrangement rather than a default documented property. Review the agreement and privacy terms before real company data is sent. [Launch](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [models/data handling](https://docs.typesafe.ai/models), [legal](https://docs.typesafe.ai/legal), [customer agreement](https://typesafe.ai/legal/mca)
- **Benchmark-publication restriction:** §2.3(f) of TypeSafe's master customer agreement prohibits publishing benchmarks or performance information about the service; §2.3(b) restricts using outputs to train an imitator or competing service. Keep any initial evaluation internal and get contractual clearance before including Jev in a public CompanyMemoryBench report. [Customer agreement](https://typesafe.ai/legal/mca)

## Evidence boundary

TypeSafe's speed, price, and workflow-quality numbers are vendor claims, not Panini measurements. Its published workflow evals use a vendor-authored workflow harness and reference probabilities from large external models rather than a fully independent, ground-truth Panini corpus; TypeSafe itself notes potential bias and says headline speed/cost gains may be at the high end of real-world gains. Accordingly, the only defensible adoption claim today is that Jev's interface fits certain narrow decisions; whether it improves Panini must be measured in a permission-scoped, source-grounded private pilot. [Technical results and caveats](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [workflow-eval method](https://evals.typesafe.ai/)
